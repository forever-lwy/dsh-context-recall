# 安装后手工验收

适用版本：dsh `0.2.1-rc.5`，插件 `0.1.2`。
本流程由用户主动安装版本后执行，开发脚本不会自动操作常用实例。

1. 在插件管理器安装 `github:forever-lwy/dsh-context-recall`（默认分支 `release` 的预构建版本）并启用。
   按实际界面的加载状态判断是否需要重启。
2. 复核实时插件清单：回忆主入口、私有全文查询、`session-controller` 应为 `active`；
   `session/modelCatalog` 应能读取。根层原生 `compaction-basic` 在 Web 中保持禁用是正常的，
   真正的压缩后端位于各 Agent preset 内。旧版安装后若控制器仍失败，应保存工作并由用户确认恢复操作。
3. 打开“设置 → 上下文压缩与回忆”，确认可读写、模型目录存在。
4. 选择一个 dsh 已配置的压缩模型并保存；刷新页面确认选择保留。
5. 输入在线向量服务地址、模型和密钥，点击测试。确认返回实际维度；
   启用在线向量后保存，再次打开页面只显示密钥配置状态。
6. 建立包含几个明确决定的测试会话；用原生界面发起压缩或 `/compact`。
   确认摘要调用使用选择的全局模型，随后对话可继续且工具调用正常。
7. 要求模型回忆被压缩前的准确细节；确认当前会话召回和原文下钻正常，
   界面显示简洁的回忆状态行。
8. 明确请求查询同工作区其他会话和跨项目历史，分别验证 workspace/all 范围。
9. 临时填写不可达的向量服务，验证测试失败信息不含密钥，模糊/全文检索仍能工作。
10. 在两个窗口同时编辑：窗口 A 保存后，窗口 B 的过期保存应提示重新读取，保留其编辑。
11. 恢复正确向量配置。修改模型或维度后，确认旧向量自动失效，重建期间本地检索仍可用。
12. 自动压缩触发比例最初应为“沿用 dsh 原生压缩策略”。改为自定义 `57.5%`，保存后刷新，
    确认仍显示 `57.5%`；切换压缩模型不应丢失比例。输入空值、16% 或 100% 应拒绝保存。
13. 在独立测试会话中，对照原生 token 用量和对话模型窗口验证阈值；
    保存本身不发起压缩，下一次自动压力检查才生效。输出预留和安全余量可能提前触发。
    分别检查已有与新会话，随后切回“沿用原生策略”；手动 `/compact` 继续可以主动压缩。

0.1.1 已完成的真实压缩模型与在线向量回忆联调记录见 [LIVE-TEST-2026-11-01.json](LIVE-TEST-2026-11-01.json)。
0.1.2 新比例的本地验证使用真实原生自动监听器、压缩事务和受控 token 用量，不会额外调用付费模型。

仍需真实联调确认的因素：所选服务的模型容量、输入限制、embedding 方言、配额、网络与实际浏览器体验。
