# 验证记录

## 0.1.2 — 全局自动压缩触发比例

日期：2026-11-01（Asia/Shanghai）。兼容基线仍为 dsh `0.2.1-rc.5`。

- GUI 提供“沿用原生策略”和自定义 `17–99%`，支持小数；`57.5%` 与持久化值 `0.575`
  精确往返，切换摘要模型不会覆盖比例。无效输入、空值和精度丢失均拒绝保存。
- 旧配置缺少 `compression.thresholdRatio` 时补为 `null`，读取不会改写原文件、修订号或模型设置。
  真实 rc.5 HTTP Remote 验证了读取、保存、重新读取、修订冲突和恢复继承。
  原生保留比例冲突会在写入配置、密钥前拒绝，原有值保持完整。
- 通过真实 rc.5 自动监听器与压缩事务验证：对话模型窗口 20,000 tokens、用量 8,000 时，
  41% 不触发，40% 到达边界触发；实际摘要仍使用全局选择的模型。
- 四种官方隔离预设、已有与新会话、逐模型阈值覆盖、设置变更后的下一次检查、
  异步容量查询前的比例快照、卸载恢复原生行为均通过。
- 原生输出预留与 headroom 上限保持有效；原始不可变配置及其属性描述符保持不变。
  固定保留 9,000 tokens 与自定义 8,000-token 阈值冲突时，先回退原生 16,000-token 阈值，
  20,000-token 会话最终只调用一次摘要模型、提交一次压缩事务。
- 仅识别原生事务前保留策略错误进行回退；取消、摘要失败或提交错误不重试。
  设置 99% 时，真实手动压缩及 `context-overflow` 恢复仍执行并使用全局摘要模型。
- 从不包含 `lib`、`node_modules` 或 Git 元数据的独立源码副本执行离线 `npm ci --ignore-scripts`、
  `npm run prepare`、`npm run check` 和全部测试；Host 与浏览器构建、类型检查及 **73 项测试全部通过**。
  独立构建与开发目录的产物按文件核对。

本轮验证使用内存或临时目录、合成会话、受控 token 用量和模拟上游，没有实际模型请求。
未在日常 profile 安装、升级、启停插件或重启服务。0.1.1 已完成的真实压缩与在线向量回忆验证
见 [LIVE-TEST-2026-11-01.json](LIVE-TEST-2026-11-01.json)；新增设置安装后的验收步骤见
[ACCEPTANCE.md](ACCEPTANCE.md)。
