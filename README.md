# dsh-context-recall

面向 **DeepSeek Harness 0.2.1-rc.5** 的上下文压缩与历史回忆插件。
以 [dsh-recall 0.2.2](https://github.com/Relistencode/dsh-recall/tree/225b940b7a361e57d9ddb495e04cef2580539d08)
为基础，适配当前会话 API，加入全局压缩模型选择、在线向量和完整 GUI 设置。

## 安装本地版本

在 dsh 界面 **插件 → 添加插件** 输入：

```text
/plugins/releases/dsh-context-recall-0.1.0.tgz
```

由用户确认安装、启用。按界面反馈处理；仅当明确显示 `restart-required` 时再安排重启。
源码目录不是安装源，不使用 `link:`，不直接修改运行实例的依赖。
如已安装原版 `dsh-recall`，先由用户在界面停用它，避免重复注册同名 `recall` 工具。

插件的 bundle patch 将原生 `compaction-basic` 行替换为其子类，保留该行已有策略配置；
同时启用官方按需全文索引。用户 profile 中后应用的自定义 patch 可以覆盖这些行，
若已自行覆盖压缩引擎，需要自行选择采用哪个引擎。本插件以原生 basic 引擎为兼容基线。

## GUI 配置

打开 **设置 → 上下文压缩与回忆**，所有本插件配置均在该页面修改，点击“保存配置”后生效。

1. **全局压缩模型**：从已配置模型中选择，也可以手动填写提供方 ID 与模型 ID。
   模型连接及其认证复用 dsh 的模型设置（包括已配置的原生 Google 模型）。
   两项同时留空时沿用原生压缩模型。保存后的选择用于下一次自动压缩、手动压缩和溢出恢复；
   正在进行的压缩使用开始时的模型，不会中途切换。
2. **在线向量模型**：输入 OpenAI 兼容的 Base URL（例如 `https://服务域名/v1`）、
   模型、API Key 和可选维度。实际请求为 `<Base URL>/embeddings`。
   维度 `0` 表示由服务决定；没有 `dimensions` 参数的服务可保持为 `0`。
   可配置批量大小、输入字符上限、超时，以及模型所需的查询/文档前缀。
   密钥字段留空保留已有值；清除使用单独的勾选项。
3. 先点击 **测试向量连接**，成功后再启用并保存。测试使用未保存的输入，
   只发送固定的 `connection test`，不索引历史、不保存密钥或设置。
4. **回忆与锚点**：可修改语义开关、后台预热、速度、覆盖率、事件聚合间隔与数量、
   默认返回数量、原文窗口、锚点开关与保留组装次数。锚点默认保留 3 次组装。

在线向量默认关闭，填写好服务后手动启用。启用后，会向该服务发送用户/助手的对话文本
（包括压缩前的历史）以及查询文本。后台预热默认遍历全部会话；关闭后台预热后，
回忆调用仍会逐批向量化全局索引中的待处理文本。结果检索范围仍默认限制当前会话。
不联网的模糊检索和原文查看始终可用。向量服务自行处理数据的政策由其提供方决定。

设置页不会回显密钥，也不使用浏览器本地存储保存密钥。密钥写入 dsh 凭据服务；
清除托管值后，如果环境中还有同名凭据，其回退值仍可能生效。
普通配置保存在 `$DSH_HOME/storages/context-recall-settings.json`，索引保存在
`$DSH_HOME/storages/context-recall-index.db`，沿用本部署现有数据挂载持久化。
这些运行数据不属于源码或版本包。

## 已保留的 recall 功能

| 能力 | 当前实现 |
| --- | --- |
| 压缩前原始记录 | 通过当前 `sessionQuery.readSession/readEvent` 读取完整日志，包括被摘要遮蔽的事件 |
| 全文检索 | 官方 SQLite FTS 检索作为回退 |
| 模糊检索 | SQLite trigram + 字符 bigram，对中文、片段和部分错字检索 |
| 语义检索 | 在线向量与模糊结果合并，默认覆盖率 ≥90% 时参与；故障自动降级 |
| 作用域 | 默认当前会话；用户明确要求时使用当前工作区或所有会话；无上下文时拒绝扩大搜索 |
| 渐进式结果 | 首次返回标题/短片段；按需查看命中列表、原文窗口和分页日志 |
| 事件聚合 | 相邻命中默认最多相隔 5 个文本块，每会话默认最多 3 个事件 |
| 压缩锚点 | 摘要 + 至多 3 条关键原文，默认 3 次组装后失效 |
| 主动回忆 | 工具说明引导模型在缺少早前细节或压缩后按需调用 |
| 轻量界面 | 中文/英文“回忆中…/回忆完成/回忆失败”状态行 |
| 索引维护 | 持久化增量索引、后台分批预热、会话移除清理、插件卸载清理 |

原版的本地 ONNX 模型替换为在线模型，不安装本地模型或下载权重。
更换向量模型、地址、维度或文本前缀会自动使旧向量失效并重新建立向量索引；原文和模糊索引保留。
参考项目 roadmap 中尚未实现的主题聚类、长期记忆蒸馏，不属于其 0.2.2 已有功能。

## 压缩行为

使用当前官方 `BasicCompactionEngine` 支持的 `summarize` 扩展点。
原生自动压力判断、保留尾部、工具调用配对、取消、单次溢出恢复和持久化事务继续由 dsh 管理。
摘要写入实际使用的提供方/模型与用量信息。失败、取消、空摘要或截断摘要不会遮蔽原文。
原生 `compaction-basic` 行中的阈值、保留策略和逐模型策略继续有效；本插件 GUI 提供摘要模型的全局覆盖。
单独停用回忆条目时，压缩后端保留原生路径，不会因缺少回忆服务而停用压缩。

## 工具用法

模型使用 `recall` 工具。默认只查当前会话，跨会话需用户明确请求。

```json
{"query":"之前决定的模型参数"}
{"query":"部署方式","scope":"workspace"}
{"query":"关键词","detail":{"sessionId":"上次返回的ID"}}
{"query":"关键词","detail":{"sessionId":"ID","seq":42,"before":3,"after":3}}
{"query":"关键词","detail":{"sessionId":"ID","browse":true,"fromSeq":42,"pageSize":20}}
```
