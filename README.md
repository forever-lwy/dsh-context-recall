# dsh-context-recall

面向 **DeepSeek Harness**（当前在 `0.2.2-rc.1` 上构建测试，不按 dsh 版本拦截加载） 的上下文压缩与历史回忆插件。
以 [dsh-recall 0.2.2](https://github.com/Relistencode/dsh-recall/tree/225b940b7a361e57d9ddb495e04cef2580539d08)
为基础，适配当前会话 API，加入全局压缩模型与触发比例、在线向量和完整 GUI 设置。

## 安装

在 DSH「插件 → 添加插件」输入下面的来源，确认安装并启用：

```text
github:forever-lwy/dsh-context-recall
```

仓库默认分支是 `release`，其中每个提交都是某次发版的源码加上构建好的 `lib/`，并去掉了 `prepare`，所以安装时不装 devDependencies、不构建。dshmarket 按默认分支上 `package.json` 的版本号判断是否有更新，点击更新时安装 `release` 的最新提交。不要安装 `master`：它只有源码，安装时会靠 `prepare` 拉全部 devDependencies 现场构建。

包名自 0.1.4 起为 `@forever-lwy/dsh-context-recall`，以免与 npm 和插件市场目录里的同名插件混淆。从旧的 `dsh-context-recall` 版本包迁移时，先卸载旧的 `dsh-context-recall`，再安装上面的来源；两者注册同一宿主行，不能同时安装。宿主行 id 和设置命名空间不变。

迁移后已有模型、向量配置、密钥和索引沿用：设置在 `storages/context-recall-settings.json`，会话索引在 `storages/context-recall-index.db`，都与包名无关。
如已安装原版 `dsh-recall`，先由用户在界面停用它，避免重复注册同名 `recall` 工具。

插件在自己的隔离组中加载官方按需全文索引，不修改应用共享查询服务或 SessionController。
压缩模型通过预设注册表公开的 `serviceFor` 接口定位会话实际使用的原生引擎，
为这些引擎实例绑定全局摘要模型和可选的自动触发比例。四个官方预设的声明、服务隔离、
原生不可变配置与类原型均保留；每次自动检查使用独立的策略快照。停用插件时恢复原实例的方法。
自行实现且不继承 `BasicCompactionEngine` 的其他压缩后端不在此覆盖范围。

是否需要重启以安装界面提示为准。不要用 `link:`、目录依赖或模块路径把源码目录接入常用 profile。

## GUI 配置

打开 **设置 → 上下文压缩与回忆**，所有本插件配置均在该页面修改，点击“保存配置”后生效。

1. **全局压缩模型**：从已配置模型中选择，也可以手动填写提供方 ID 与模型 ID。
   模型连接及其认证复用 dsh 的模型设置（包括已配置的原生 Google 模型）。
   两项同时留空时沿用原生压缩模型。保存后的选择用于下一次自动压缩、手动压缩和溢出恢复；
   正在进行的压缩使用开始时的模型，不会中途切换。
2. **自动压缩触发比例**：选择沿用原生策略，或输入全局 `17–99%`（支持小数）。
   比例基于当前**对话模型**的上下文窗口，与摘要模型的窗口无关。
   例如对话模型窗口为 200,000 tokens，设置 60% 对应 120,000 tokens；
   输出预留和原生安全余量可能使实际阈值更低。官方预设默认比例为 80%，保留最近约 16%。
   自定义比例还须高于你另设的原生保留比例，否则保存会提示冲突。
   保存后用于已有与新会话的下一次自动压力检查，不会立即发起压缩；
   手动 `/compact` 和溢出恢复继续使用原生行为。
3. **在线向量模型**：输入 OpenAI 兼容的 Base URL（例如 `https://服务域名/v1`）、
   模型、API Key 和可选维度。实际请求为 `<Base URL>/embeddings`。
   维度 `0` 表示由服务决定；没有 `dimensions` 参数的服务可保持为 `0`。
   可配置批量大小、输入字符上限、超时，以及模型所需的查询/文档前缀。
   密钥字段留空保留已有值；清除使用单独的勾选项。
4. 先点击 **测试向量连接**，成功后再启用并保存。测试使用未保存的输入，
   只发送固定的 `connection test`，不索引历史、不保存密钥或设置。
5. **回忆与锚点**：可修改语义开关、后台预热、速度、覆盖率、事件聚合间隔与数量、
   默认返回数量、原文窗口、锚点开关与保留组装次数。锚点默认保留 3 次组装。

在线向量默认关闭，填写好服务后手动启用。启用后，会向该服务发送用户/助手的对话文本
（包括压缩前的历史）以及查询文本。后台预热只在有新文本入索引后分批进行，
没有待处理文本时不占用定时器；服务出错时按 30 秒起、最长 30 分钟的间隔退避重试。
关闭后台预热后，回忆调用仍会逐批向量化全局索引中的待处理文本。结果检索范围仍默认限制当前会话。
不联网的模糊检索和原文查看始终可用。向量服务自行处理数据的政策由其提供方决定。

设置页不会回显密钥，也不使用浏览器本地存储保存密钥。密钥写入 dsh 凭据服务；
清除托管值后，如果环境中还有同名凭据，其回退值仍可能生效。
普通配置保存在 `$DSH_HOME/storages/context-recall-settings.json`，索引保存在
`$DSH_HOME/storages/context-recall-index.db`；独立全文索引保存在
`$DSH_HOME/storages/context-recall-fulltext.db`，沿用本部署现有数据挂载持久化。
这些运行数据不属于源码或版本包。

## 已保留的 recall 功能

| 能力 | 当前实现 |
| --- | --- |
| 压缩前原始记录 | 通过当前 `sessionQuery.readSession/readEvent` 读取完整日志，包括被摘要遮蔽的事件 |
| 全文检索 | 官方 SQLite FTS 检索作为回退 |
| 模糊检索 | SQLite trigram + 字符 bigram，对中文、片段和部分错字检索 |
| 语义检索 | 在线向量与模糊结果合并，默认覆盖率 ≥90% 时参与；故障自动降级 |
| 作用域 | 默认当前会话；用户明确要求时使用当前工作区或所有会话；无上下文时拒绝扩大搜索 |
| 渐进式结果 | 首次返回标题/短片段；按需查看命中列表、原文窗口和分页日志 |
| 事件聚合 | 相邻命中默认最多相隔 5 个文本块，每会话默认最多 3 个事件 |
| 压缩锚点 | 摘要 + 至多 3 条关键原文，默认 3 次组装后失效 |
| 主动回忆 | 工具说明引导模型在缺少早前细节或压缩后按需调用 |
| 轻量界面 | 中文/英文“回忆中…/回忆完成/回忆失败”状态行 |
| 索引维护 | 事件驱动增量索引（见下节）、按需分批向量化、会话删除清理、插件卸载清理 |
| 标题检索 | 会话标题单独建 trigram 索引，标题来自会话日志的标题事件，缺失时回填宿主标题 |

原版的本地 ONNX 模型替换为在线模型，不安装本地模型或下载权重。
更换向量模型、地址、维度或文本前缀会自动使旧向量失效并重新建立向量索引；原文和模糊索引保留。
参考项目 roadmap 中尚未实现的主题聚类、长期记忆蒸馏，不属于其 0.2.2 已有功能。

## 索引如何保持最新（0.2.0 起）

索引只收录真正的对话内容：用户亲自发送的消息和助手回复的文字部分。宿主注入的
运行时上下文、时间戳、技能目录、记忆快照等消息，以及工具调用参数，都不入索引，
也不会被发送去向量化。0.2.0 首次启动时会按新规则从会话日志重建一次索引（向量随之重建）。

- **实时**：插件监听会话事件，只处理用户消息、助手消息和标题事件，约 1.5 秒防抖后增量写入。
  某个会话在本进程中第一次出现时读取一次完整日志补齐，之后不再读日志。
- **对账**：启动约 15 秒后一次，此后每小时一次。只读取持久化 revision 发生变化的会话，
  并清理已删除的会话；尚未落盘的实时会话不会被误删。
- **查询**：检索前只把排队中的实时事件写入索引，不再逐个读取会话日志。
- **向量**：检索时直接从 SQLite 流式计算相似度并只保留前若干条，不把全部向量常驻内存；
  会话或工作区范围在排序前过滤。

0.1.x 每 30 秒读取并解码全部已打开会话的完整日志，常驻内存和空闲 CPU 都偏高，0.2.0 起不再这样做。

## 压缩行为

使用当前官方 `BasicCompactionEngine` 支持的 `summarize` 扩展点，接入会话预设内的实际实例。
原生自动压力判断、保留尾部、工具调用配对、取消、单次溢出恢复和持久化事务继续由 dsh 管理。
摘要写入实际使用的提供方/模型与用量信息。失败、取消、空摘要或截断摘要不会遮蔽原文。
“沿用原生策略”保留 `compaction-basic` 的默认和逐模型阈值；自定义比例全局覆盖两者。
保留尾部、输出预留、安全余量和逐模型摘要上限仍由原生策略控制。
若后续加载的自定义后端保留比例与已保存的全局比例冲突，该引擎继续使用原生自动策略并记录警告；
固定 token 保留量与新比例发生容量冲突时，同样回退原生自动策略，不削减保留内容。
已打开的会话和随后创建的会话均能使用设置；原生后端热加载后会重新绑定。
单独停用回忆条目时恢复原生摘要路径，不会停用压缩后端。

## 工具用法

模型使用 `recall` 工具。默认只查当前会话，跨会话需用户明确请求。

```json
{"query":"之前决定的模型参数"}
{"query":"部署方式","scope":"workspace"}
{"query":"关键词","detail":{"sessionId":"上次返回的ID"}}
{"query":"关键词","detail":{"sessionId":"ID","seq":42,"before":3,"after":3}}
{"query":"关键词","detail":{"sessionId":"ID","browse":true,"fromSeq":42,"pageSize":20}}
```

```sh
npm ci
npm run check
npm run build
npm test
```

依赖不引用临时上游目录。需要离线备用的本地版本包时运行 `npm pack --pack-destination ../releases`，每版使用新的版本号和文件名。
测试使用临时目录、内存 SQLite、真实 rc.5 服务和模拟上游，不读取实际会话或使用生产模型凭据。
只有用户在日常界面安装和配置后，才能完成真实浏览器与实际模型的最终联调。

发版：在 `master` 上开发和推送不会触发任何构建。改完后递增 `package.json` 版本并提交，打同名标签并推送，例如 `git tag v0.1.4 && git push origin master v0.1.4`。GitHub Actions（`.github/workflows/release.yml`）只在 `v*` 标签推送时运行：检查标签与版本一致，按 lockfile `npm ci`，由 `scripts/release.mjs` 构建、测试，在 `release` 分支上追加一个发布提交（源码加 `lib/`，去掉 `prepare`；父提交是上一个发布提交和该标签的源码提交）并推送。`release` 已有同一或更高版本时会拒绝发版。`npm run release` 可在本地对已打标签的提交生成同样的发布提交（不推送）。
